# Cucumber Feature 파일 생성 Skill

행위를 분석하여 Cucumber `.feature` 파일을 생성합니다.

## 입력

$ARGUMENTS - 테스트할 행위명

**예시:**
- `/cucumber 선물전송`
- `/cucumber 카테고리생성`
- `/cucumber Option.decrease`

## 핵심 원칙

1. **프로덕션 코드 수정 금지**: 테스트 코드만 작성한다.
2. **구현이 아닌 행동을 검증한다**: 내부 구현에 의존하는 시나리오는 작성하지 않는다.
   - 나쁜 예: `Then optionRepository.save()가 호출된다`
   - 좋은 예: `Then "기본 옵션"의 재고는 7개이다`
3. **외부 관찰 가능한 결과만 검증한다**: 사용자가 볼 수 있는 결과(응답, 상태 변경)를 검증한다.

## 인수 테스트 품질 기준

생성된 시나리오는 다음을 모두 만족해야 한다:

1. **행동 중심**: 구현이 아닌 사용자 관점의 시나리오인가?
2. **외부 관찰 가능**: 사용자가 볼 수 있는 결과를 검증하는가?
3. **계약 보호**: 핵심 비즈니스 규칙을 보호하는가?
4. **실패 의미 전달**: 실패 시 비즈니스 의미를 바로 알 수 있는가?
5. **리팩토링 내성**: 내부 구현이 바뀌어도 유지되는가?

## 테스트 레벨 판단

시나리오를 작성하기 전에 다음을 확인한다:

| 질문 | Cucumber에 적절하면 |
|------|-------------------|
| 이 검증은 사용자가 볼 수 있는 결과인가? | Yes |
| 내부 구조가 바뀌면 이 테스트가 함께 깨지는가? | No |
| 이 관심사는 통합/단위가 더 적절한가? | No |
| 테스트 이름만 보고 계약 위반인지 바로 알 수 있는가? | Yes |

해당하지 않으면 Cucumber가 아닌 단위/통합 테스트를 권장한다.

## 실행 절차

### 1단계: 코드 분석

행위와 관련된 코드를 찾아 분석한다:

- 관련 Controller, Service, Entity 코드 읽기
- API 엔드포인트, 요청/응답 형식 파악
- 성공/실패 경로, 예외 조건 확인

### 2단계: 시나리오 도출 (outside-in)

1. 사용자 행동 정의 → 기능 파악
2. 성공/실패 기준 정의 → 인수 조건 도출
3. 관찰 가능한 결과 정의 → 시나리오 도출

### 3단계: Feature 파일 제안

`.feature` 파일 내용을 **사용자에게 보여준다**.
반드시 AskUserQuestion 도구를 사용하여 확인을 받는다.

**확인 항목:**
- 시나리오가 행동 중심인지
- 누락된 시나리오가 없는지
- 시나리오 이름이 비즈니스 의미를 전달하는지

### 4단계: 파일 생성

사용자가 승인하면 `.feature` 파일을 생성한다.

## Feature 파일 작성 규칙

### 언어

- Feature, Scenario 설명: **한글**
- 키워드(Feature, Scenario, Given, When, Then): **영문 Gherkin**

### 구조

```gherkin
Feature: [기능명]
  [기능에 대한 한 줄 설명]

  Background:
    Given [공통 사전 조건들]

  Scenario: [상황]_[행동]하면_[결과]한다
    Given [추가 사전 조건]
    When [사용자 행동]
    Then [관찰 가능한 결과]

  Scenario: [실패 시나리오]
    ...
```

### Scenario 이름 규칙

테스트 이름은 설계 도구다. 응답 코드만이 아닌 행동의 결과를 담는다.

| | 예시 |
|---|---|
| 나쁜 예 | `Scenario: 선물 전송 API 성공` |
| 좋은 예 | `Scenario: 선물이 전송되면 재고가 감소한다` |

### 시나리오 포함 기준

| 필수 | 선택 |
|------|------|
| 성공 시나리오 | 경계값 |
| 핵심 실패 시나리오 (비즈니스 규칙 위반) | 권한/인증 |
| 상태 변경 검증 | 동시성 |

## 파일 위치

```
src/test/resources/features/
  └── [feature-name].feature
```

## 예시

### 입력
```
/cucumber 선물전송
```

### 출력
```gherkin
Feature: 선물 전송
  사용자는 상품 옵션을 선택하여 다른 사용자에게 선물을 보낼 수 있다.

  Background:
    Given "테스트 카테고리"에 10000원짜리 "테스트 상품"이 있다
    And "테스트 상품"에 재고 10개인 "기본 옵션"이 있다
    And "보내는사람"과 "받는사람" 회원이 있다

  Scenario: 선물이 전송되면 재고가 감소한다
    When "보내는사람"이 "받는사람"에게 "기본 옵션" 3개를 선물한다
    Then 응답 상태코드는 200이다
    And "기본 옵션"의 재고는 7개이다

  Scenario: 재고가 부족하면 선물을 보낼 수 없다
    When "보내는사람"이 "받는사람"에게 "기본 옵션" 100개를 선물한다
    Then 응답 상태코드는 500이다
    And "기본 옵션"의 재고는 10개이다

  Scenario: 존재하지 않는 옵션으로 선물을 보낼 수 없다
    When "보내는사람"이 "받는사람"에게 존재하지 않는 옵션을 선물한다
    Then 응답 상태코드는 500이다
```
