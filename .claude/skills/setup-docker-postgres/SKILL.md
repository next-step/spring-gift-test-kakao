PostgreSQL + Docker Compose 통합 테스트 환경을 구성한다. 아래 단계를 순서대로 수행한다.

## 1단계: docker-compose.yml 작성

프로젝트 루트에 `docker-compose.yml`을 생성한다.

PostgreSQL 서비스 구성:
- 이미지: `postgres:16-alpine`
- 포트: `5432:5432`
- 환경변수: `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`
- healthcheck: `pg_isready` 명령으로 DB 준비 상태를 확인한다
- volume: 데이터 영속성 (선택)

```yaml
services:
  postgres:
    image: postgres:16-alpine
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: gift_test
      POSTGRES_USER: test
      POSTGRES_PASSWORD: test
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U test -d gift_test"]
      interval: 3s
      timeout: 3s
      retries: 5
```

## 2단계: Spring 프로파일 분리

`src/test/resources/application-cucumber.properties`를 생성하여 PostgreSQL 설정을 분리한다.

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/gift_test
spring.datasource.username=test
spring.datasource.password=test
spring.datasource.driver-class-name=org.postgresql.Driver
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
spring.jpa.hibernate.ddl-auto=create-drop
```

기존 H2 설정(`application.properties` 또는 기본 설정)은 단위 테스트용으로 유지한다.

## 3단계: PostgreSQL 드라이버 의존성 추가

build.gradle에 PostgreSQL JDBC 드라이버를 추가한다.

```groovy
runtimeOnly 'org.postgresql:postgresql'
```

## 4단계: 테스트 설정에 프로파일 적용

Cucumber Spring Configuration에 `@ActiveProfiles("cucumber")`를 추가한다.

```java
@CucumberContextConfiguration
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@ActiveProfiles("cucumber")
public class CucumberSpringConfiguration {
    // ...
}
```

## 5단계: Gradle 태스크 작성

build.gradle에 Docker Compose 제어 태스크를 추가한다.

```groovy
tasks.register('dockerUp', Exec) {
    commandLine 'docker', 'compose', 'up', '-d', '--wait'
}

tasks.register('dockerDown', Exec) {
    commandLine 'docker', 'compose', 'down'
}

tasks.register('cucumberTest', Test) {
    dependsOn 'dockerUp'
    useJUnitPlatform()
    finalizedBy 'dockerDown'
    // Cucumber 테스트만 실행하도록 필터링
}
```

- `--wait` 플래그로 healthcheck가 통과할 때까지 대기한다
- `finalizedBy`로 테스트 성공/실패와 무관하게 컨테이너를 정리한다

## 6단계: 데이터 격리

각 시나리오 실행 전 테이블을 초기화한다.

```java
@Before
public void cleanup() {
    jdbcTemplate.execute("TRUNCATE TABLE ... CASCADE");
}
```

PostgreSQL에서는 `TRUNCATE ... CASCADE`로 FK 제약 조건을 포함하여 초기화할 수 있다.

## 7단계: SQL 호환성 확인

기존 H2 전용 SQL 문법이 있다면 PostgreSQL 호환으로 수정한다.

주의할 차이점:
- H2의 `IDENTITY` → PostgreSQL의 `GENERATED BY DEFAULT AS IDENTITY` 또는 `SERIAL`
- H2의 `TRUNCATE TABLE ... RESTART IDENTITY` 문법 차이
- 예약어 차이 (예: `user`, `order` 등은 PostgreSQL에서 예약어)

## 8단계: 검증

```bash
./gradlew cucumberTest
```

- Docker Compose로 PostgreSQL이 자동 시작되는지 확인한다
- 모든 Cucumber 시나리오가 PostgreSQL 위에서 통과하는지 확인한다
- 테스트 완료 후 컨테이너가 정리되는지 확인한다

## H2 테스트와의 공존

기존 `./gradlew test`는 H2로 빠르게 실행하고, `./gradlew cucumberTest`는 PostgreSQL로 실행하는 구조를 유지할 수 있다. 두 태스크를 분리하여 개발 중에는 H2로 빠른 피드백을, CI에서는 PostgreSQL로 정확한 검증을 수행한다.
